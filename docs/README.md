# Jixu 私人工程资产

这个目录保存 Jixu 在真实开发过程中形成的个人方法论、技术判断和阶段复盘。
它不是公开文档，也不是规范的事实来源。

## 权威关系

1. `SPEC.md`：公开行为和架构的规范来源；
2. `AGENTS.md`：仓库开发与协作规则；
3. `docs/stages/*.md`：私有的背景、推理、实现过程和经验沉淀。

如果这里的描述与当前 `SPEC.md` 或实现冲突，应先核对代码与证据，再按照
spec evolution 流程修正规范和实现，不能把阶段复盘当成隐藏规范。

## 阶段记录规则

每个阶段通过验证后、向 Zander 汇报完成前，新建一份：

```text
docs/stages/NN-<stage-slug>.md
```

内容至少包含：

- 为什么做；
- 为什么选择这套架构；
- 具体怎么实现；
- 使用了哪些技术；
- 哪些验证支持结论；
- 遇到了什么问题、学到了什么；
- 哪些内容明确留给下一阶段。

## 隐私边界

`/docs/` 通过当前仓库的 `.git/info/exclude` 排除。该规则只存在于本地
`.git` 目录，不会提交到 GitHub。

注意：这意味着这些文件也不会随着普通 `git clone` 自动备份到其他电脑。
需要跨设备保存时，应使用独立 private repository 或其他私人存储，不能把它们
强制加入当前 public repository。
